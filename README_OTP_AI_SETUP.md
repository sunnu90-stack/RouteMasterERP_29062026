# NavGati ERP OTP & AI Setup

## A. SMS OTP Auto-Read Setup

### Android
1. Build and install the Android app on a physical device.
2. The app now uses `sms_autofill` and obtains the app hash automatically.
3. Use this SMS format for automatic OTP detection:

```
Your NavGati OTP is 123456.
@<YOUR_DOMAIN> #<APP_HASH>
```

4. Replace `<YOUR_DOMAIN>` with a domain you control and `<APP_HASH>` with the value shown in the login screen under "Android SMS auto-read setup." This app hash is generated by `SmsAutoFill().getAppSignature()`.

5. Add the number and domain to your SMS provider settings if required.

### iOS
- On iOS, use the one-time code format and ensure automatic code suggestions are enabled in Settings.
- Example SMS:

```
Your NavGati OTP is 123456.
```

### Notes
- Auto-read requires native mobile; it will not work on Flutter web.
- If you see a browser reCAPTCHA page, you are on web or your Firebase Phone Auth is not configured for native mobile.
- Use Firebase test phone numbers for development to avoid real SMS and reCAPTCHA.

## B. AI Diagnostics & Live Setup

### AI keys
- Set `MAPS_KEY` for Google Maps Directions and one or more of `GEMINI_API_KEY`, `GROQ_API_KEY`, `SARVAM_API_KEY`, or `OPENROUTER_API_KEY` in the environment of the shell that launches `run_secure.bat`.
- In PowerShell, for example, set `$env:MAPS_KEY` and `$env:GEMINI_API_KEY` before running `.\run_secure.bat`. The script passes those values to Flutter as build-time defines; the app configuration has no embedded key defaults.
- These values are still extractable from a client app; use a backend proxy for production credentials.

### How the app chooses AI
- If Gemini key is provided, the app tries Gemini first.
- If Gemini fails, it tries the configured Groq, Sarvam, and OpenRouter providers.
- If all configured providers fail or keys are missing, the app uses a local heuristic fallback.

### Diagnostics
- Open the AI chat screen and tap "Show details" under AI Diagnostics.
- The app displays the last AI request status, including which provider was reached and any error condition.

### Common issues
- `403` means the API key is invalid or not enabled.
- `404` means the model or endpoint is not found.
- `429` means rate limiting.
- On mobile, ensure internet access and correct API key values.

## C. Web OTP and reCAPTCHA

- Firebase Phone Auth on web requires reCAPTCHA and cannot be bypassed safely.
- For a direct OTP experience, use the app on Android or iOS and set up native app verification.
- For development on web, use Firebase test phone numbers configured in the Firebase Console.

## D. Email sign-in and first-login location

- In Firebase Console, open **Authentication → Sign-in method** and enable **Email/Password**.
- The login screen supports email/password sign-in, account creation, and password-reset links in addition to phone OTP.
- If the user opts in to Location & routing in the privacy consent, they can request a current GPS fix on first login, review the detected place/coordinates, and confirm it. The confirmed coordinates are stored only in encrypted local app storage. They can skip GPS or leave location consent off.
- Drivers separately choose **Start Sharing Location** in Driver Mode to share foreground GPS with their fleet during a trip; sharing stops when they stop it or leave Driver Mode. Live traffic suggestions use that trip location and require a configured Google Maps Directions API key. No background location permission is requested.
- Route suggestions refresh at the interval selected in Live Tracking and never change navigation automatically. Green Impact totals use accepted, deduplicated route comparisons; diesel and CO₂e are estimates, not issued carbon credits. Independent verification and registry issuance are required for tradable credits.
- Android declares coarse and fine location permissions; iOS requests foreground location only and explains both opt-in uses in `NSLocationWhenInUseUsageDescription`.

## E. Dashboard push notifications

- The admin dashboard writes broadcasts to Firestore. The Firebase Cloud Function in `functions/` sends the corresponding FCM notification to the selected topic; foreground users also see the broadcast in the app.
- Install and deploy the function with a Firebase project account that has Cloud Functions deployment access:

  ```powershell
  npm install --prefix functions
  npm --prefix functions run lint
  firebase functions:secrets:set BROADCAST_ADMIN_UIDS
  firebase deploy --only functions:sendBroadcastPush
  ```

- When prompted for `BROADCAST_ADMIN_UIDS`, enter the comma-separated Firebase Authentication UIDs allowed to send broadcasts from the admin dashboard. The function rejects broadcasts from UIDs not on this list. Do not put this allowlist in the Flutter app.
- Cloud Functions deployment requires the Firebase project to have billing enabled. Users need an active Firebase Authentication account and their FCM topic subscription.
- On Android 13 and later, allow NavGati notifications when prompted. The app subscribes devices to `all_users` and paid subscribers to `paid_tier`.
